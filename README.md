# 🎶 Музыкальное лото — Telegram-бот

Бот собирает таблицы для музыкального лото из вашего списка песен.
Песни звучат в порядке списка, а таблицы выигрывают строго по одной — без
«двойных» побед и без линий, собранных раньше времени.

## Что умеет

- Принимает список песен текстом или `.txt`-файлом.
- Убирает нумерацию, маркеры списка и дубликаты.
- Делает таблицы **6×6** или **7×7** — сколько скажете.
- Спрашивает, на какой песне должен выиграть **первый** билет.
- Собирает таблицы так, чтобы:
  - до первого победного билета ни одна таблица не собрала ни строку, ни столбец;
  - на выбранной песне выиграл первый билет;
  - каждая следующая песня закрывала ровно одну следующую таблицу;
  - в один ход не выигрывали два билета.
- Присылает таблицы картинками PNG и отдельный **ключ ведущего** — какая
  таблица, на какой песне и какой линией выигрывает.
- По кнопке собирает новый вариант с теми же параметрами.

## Как пользоваться

1. Отправьте боту `/start`.
2. Пришлите список — по одной песне в строке:

   ```
   1. Моргенштерн - кадилак
   2. IOWA - 140
   3. Кино - Звезда по имени Солнце
   ...
   ```

   Нумерация не обязательна. Можно отправить файл `.txt`.
3. Выберите размер таблицы кнопкой: **6×6** или **7×7**.
4. Введите количество таблиц.
5. Введите песню, на которой выиграет первый билет: номер из подсказанного
   диапазона или название песни.

Бот проверит параметры, соберёт таблицы, ещё раз проверит правила симуляцией
игры и отправит:

- картинки таблиц;
- ключ ведущего (не показывайте его игрокам).

В ключе для каждой таблицы указано, на какой песне она выигрывает и какая
линия собирается — например, «таблица 3, строка 2». Ключ можно использовать,
чтобы вести игру и проверять победителей.

После выдачи доступны кнопки:

- **🔁 Другой вариант** — новые таблицы с теми же параметрами;
- **🎯 Другая песня** — изменить первый победный билет;
- **📐 Другой размер** — вернуться к выбору 6×6 / 7×7 (и количеству таблиц);
- **🆕 Новый список** — начать заново.

## Важные ограничения

Они не прихоть бота, а следствие правил. В каждой линии таблицы, кроме
выигрышной, должна стоять песня, которая прозвучит **позже** победной. Иначе
линия соберётся раньше. Поэтому каждой таблице нужно минимум `size` песен после
её победной песни.

Отсюда:

- минимум песен в списке: **36** для 6×6 и **49** для 7×7 (внутри одной таблицы
  песни не повторяются);
- максимум таблиц: `песен − 2 × размер + 1`;
- первый победный билет: с номера `размер` по номер
  `песен − размер − таблиц + 1`.

Примеры:

| Песен | Таблица | Таблиц | Первый билет | Последний победный |
|------:|:-------:|-------:|:-------------|:-------------------|
| 50 | 6×6 | 10 | №6–35 | №15–44 |
| 50 | 7×7 | 5 | №7–39 | №11–43 |
| 40 | 6×6 | 5 | №6–30 | №10–34 |
| 49 | 7×7 | 36 | только №7 | №7 |

Если хочется, чтобы первый билет выпал позже, есть два пути: уменьшить
количество таблиц или добавить песни в список.

> Почему нельзя выиграть на самой последней песне? Потому что у таблицы есть и
> другие линии. К последней песне все они уже были бы собраны, и таблица
> выиграла бы раньше. Поэтому после победной песни каждой таблице нужен запас.

## Как устроена генерация

Для каждой таблицы:

1. Выбирается выигрышная линия — строка или столбец.
2. В ней размещается победная песня и `size − 1` песен, прозвучавших раньше.
3. В каждой остальной линии ставится «блокер» — песня, которая прозвучит позже
   победной. Пока блокер не сыграл, линия собраться не может.
4. Остальные клетки заполняются случайными песнями из списка.

Поэтому таблица выигрывает ровно на своей песне: выигрышная линия собирается
только тогда, когда прозвучит победная песня, а все остальные линии заблокированы
песнями из будущего. После сборки бот проигрывает всю игру и сверяет порядок
победителей.

Внутри одной таблицы все песни разные. В разных таблицах наборы и порядок
отличаются — какая-то песня может быть в одной таблице и отсутствовать в другой.

## Установка

Нужен Python 3.10+.

### Windows

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
python bot.py
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
python bot.py
```

В `.env` положите токен от [@BotFather](https://t.me/BotFather):

```env
BOT_TOKEN=123456789:AA...
```

Можно не создавать `.env`, а задать переменную окружения `BOT_TOKEN` вручную.

### Docker

```bash
docker build -t music-lotto .
docker run --rm --env-file .env music-lotto
```

В образ устанавливаются шрифты DejaVu с кириллицей.

## Автономный .exe для Windows

Можно собрать бота в один файл, которому не нужны Python и установка
зависимостей:

```powershell
python build_exe.py
```

Готовый файл: `dist\MusicLottoBot.exe` (~26 МБ). Его можно отправить любому
человеку — достаточно запустить двойным щелчком.

Скрипт сборки берёт токен из `.env` (или из переменной `BOT_TOKEN`) и
**вшивает его в exe**. Поэтому:

- получателю не нужно ничего настраивать;
- токен находится внутри файла — не выкладывайте exe в открытый доступ;
- с одним токеном одновременно может работать только один экземпляр бота.
  Если запустить второй, Telegram вернёт `Conflict: terminated by other
  getUpdates request`. Остановите лишний экземпляр;
- `.env` рядом с exe имеет приоритет над вшитым токеном — удобно, если
  получатель хочет подключить своего бота.

Проверка собранного файла без запуска игры:

```powershell
dist\MusicLottoBot.exe --check-token
dist\MusicLottoBot.exe --selftest
```

`--check-token` показывает, откуда взят токен (сам токен маскируется), а
`--selftest` собирает и рисует пробную таблицу, проверяя, что Pillow и шрифты
работают.

Если при запуске exe на чужом компьютере Windows покажет «Windows protected
your PC», нужно нажать «Подробнее» → «Выполнить всё равно»: файл не подписан
сертификатом.

Чтобы собрать exe с другим токеном, измените `.env` и запустите
`python build_exe.py` снова.

### Одиночный .py-файл

Если получателю удобнее запускать Python-скрипт, передайте папку проекта или
соберите один файл вручную: код бота лежит в `bot.py` и пакете `music_lotto`.
При запуске без токена бот спросит его в консоли и сохранит в `.env` рядом с
собой.

## Шрифты

Для картинок нужен шрифт с кириллицей. Бот ищет Arial (Windows), DejaVu Sans
или Liberation Sans (Linux), Arial (macOS). Если шрифт не найден, таблицы
приходят одним `.txt`-файлом — играть можно, но картинок не будет.

Свой шрифт можно положить в `assets/fonts/bold.ttf` и
`assets/fonts/regular.ttf` или указать пути в переменных
`LOTTO_FONT_BOLD` и `LOTTO_FONT_REGULAR`.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты проверяют:

- что таблицы выигрывают ровно в задуманном порядке;
- что до первого билета нет собранных линий;
- что в один ход не выигрывают две таблицы;
- что внутри таблицы нет повторяющихся песен;
- границы допустимых параметров;
- разбор списка и поиск песни по названию;
- отрисовку PNG и отправку сообщений.

```

```

## Если что-то не работает

- **«Не задан BOT_TOKEN»** — проверьте `.env` или переменную окружения.
- **«Для таблицы 7×7 нужно минимум 49 песен»** — добавьте песни или выберите 6×6.
- **«Первый победный билет должен быть на песне с №… по №…»** — уменьшите
  количество таблиц, добавьте песни или сдвиньте первый билет раньше.
- **Не приходят картинки** — не найден шрифт с кириллицей; установите
  `fonts-dejavu-core` (Linux) или положите свой шрифт в `assets/fonts/`.
- **Кнопка «устарела»** — сценарий уже перешёл дальше; начните заново `/start`.
- **`Conflict: terminated by other getUpdates request`** — с этим токеном уже
  работает другой экземпляр бота (на вашем компьютере, сервере или у человека,
  которому вы отдали exe). Одновременно должен работать только один.

## Примечания

- Бот не хранит данные на диске: состояние сессии живёт в памяти процесса.
  После перезапуска текущая игра сбрасывается.
- Для игры нужен только один экземпляр бота на токен (long polling).
- Не коммитьте `.env` — там токен.
